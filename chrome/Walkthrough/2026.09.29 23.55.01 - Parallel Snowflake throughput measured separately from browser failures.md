# Parallel Snowflake and browser transport measurements

The Chrome subproject remains a standalone JavaScript/WebAssembly extension using the tor-js
public gateway. The user requested comparative download tests of that gateway, several Snowflake
connections, and other available paths. Production extension code was not changed.

The gateway completed seven verified 1 MiB samples across three browser sessions. Three native
Snowflake clients completed concurrent samples at 345.0 kB/s aggregate. Their directory cache
was prepared from an earlier successful test; guard state was independent. Individual native
Snowflake bridges, direct Tor, and meek also produced verified results. The two obfs4 addresses
failed within the fixed connection deadline.

The browser webtor-rs package had a retired directory URL. Mapping its two directory requests to
the current location removed the 404, but three WebRTC attempts and the tested WebSocket paths
still did not produce downloads. Native results must not be presented as proof that the pure
Chrome Snowflake client works. The published WebTunnel description also differed from its WASM
implementation. See the conditions, results, and source evidence in
[TransportBenchmarks](../docs/TransportBenchmarks.md); raw measurement artifacts are under build/speed.

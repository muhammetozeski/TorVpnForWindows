# Walkthrough guide

Read this complete guide on first use. The aim is to transfer current project context and useful
experience with the least reading and writing. This token-saving rule applies only to Walkthrough.

Select records by their descriptive filenames before reading their contents. Start with the newest
record and the newest accumulation record, if one exists. Read relevant records after that
accumulation, then search older filenames only for a specific missing lesson. A newer record can
correct an older one; check titles for a later correction when using an old lesson. Stop reading
when the current purpose, state, and relevant experience are understood. Do not scan unrelated
projects, chat histories, or Git history to manufacture context.

Write a new record when an observed result, lesson, or state change affects later work, including
before leaving unfinished work. Use the actual local creation time in the filename:
`yyyy.MM.dd HH.mm.ss - Descriptive event and result.md`. Obtain it from `Get-Date`; do not invent a
past time or overwrite an existing record. Do not create an empty record just because work happened.

Use a few concise paragraphs to convey the current project frame, the observation that changed
the approach, the outcome, and what that means for the next contributor. Keep the broader project
context, not just the latest event. Preserve unresolved constraints until there is evidence they
are resolved. Distinguish tested results from assumptions and plans. Do not claim user approval
that was never given.

Link to `docs` for durable technical details rather than copying them. Do not narrate Git changes,
list files or commands, copy raw logs, or add personal apologies and praise. Reuse already obtained
evidence; writing a record does not justify another investigation or repeated tests.

When too many records are needed to understand the current state, create a new dated accumulation
record with `Accumulation` in its title and the covered range stated inside. Preserve useful
earlier lessons and turning points. Do not rewrite or delete old records. New corrections belong
in a new descriptive record; an already known older record may receive a short timestamped
correction without an archive-wide maintenance pass. Do not strike out a statement merely because
it was true earlier and the situation later changed.

Check that the new title supports selection, the context matches observed results, and its links
exist. Keep the record as short as possible without removing conditions a later contributor needs.

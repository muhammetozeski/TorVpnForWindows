# Walkthrough: project context and experience

Read this guide completely on first use. Re-reading the same unchanged guide within one
session is unnecessary. Walkthrough aims to transfer current context and approach-changing
experience with the least reading needed; this objective applies only to Walkthrough.

Select records by filename before opening them. Find the newest dated context and the newest
record whose name contains `Birikim`, if present. Read the newest context and the needed part
of that accumulation. Then select relevant records written after the accumulation. For an older
subject, search its filenames and check whether a newer record changes that lesson. Stop when
the current direction and relevant experience are understood; do not read the whole archive.

Use the evidence already gathered during the task. Do not scan Git history, unrelated projects
or conversations merely to fill a record. Never invent earlier experience or assume an older
obstacle disappeared without evidence. Validate current state only where the new work needs it.

Write each meaningful result as a new Markdown file named with the actual local creation time,
including seconds, followed by a descriptive subject. For example, use the PowerShell format
`yyyy.MM.dd HH.mm.ss` and a title describing the observation and resulting approach. Keep project
documentation in English; the marker `Birikim` identifies an accumulation record.

A few short paragraphs should carry the project's current context, the observation that changed
the approach, the verified result, and what the next reader needs to know. Do not list commits,
files, tool calls or every attempted step. Link to Docs for reusable method details instead of
copying them. Include a short current frame so the latest event is not mistaken for the whole project.

Create a new accumulation record only when understanding the same context increasingly requires
many older records. State the covered subjects and last covered record, then combine the valid
context and lessons without rewriting or deleting old records. Correct a disproved conclusion
in a new, searchable record; an optional timestamped correction can be appended to an already
known older record while leaving its original account readable.

Record a result when it affects later work and before leaving the task. No new knowledge means
no empty record. Check the new record's links, descriptive filename and factual claims. Project
guidance in `AGENTS.md` points readers here without requiring access to a personal skill directory.
